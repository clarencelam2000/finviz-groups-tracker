Design intent — rev 2026-08-09

The ticket is live, or it isn’t a ticket

  • Status + price lead, honestly. Status (Triggered / Setting up / Gapped) is read straight from WS3, tagged “as of 10:05.” No minute-precise “triggered 09:58” — we only snapshot twice a day, so that precision would be a lie.
  • Price is an editable override. Defaults to the last snapshot; when you check at 11am and it’s moved, type the real number and both gates + sizing recompute. (Real live quotes → #287, when Alpaca lands.)
  • Two don’t-chase gates. ATR-from-LoD (intraday, 0.8/1.0, from WS3) for “am I chasing today,” plus ATR-ext-from-50MA (positional, existing 2.5/4.0 config) for “is it rubber-banded.” Both above the stop menu because chase-risk gates stop choice.
  • Stop menu is the one interaction — a segmented control live-recomputing risk/share, %risk, and shares. Four bases: prior low ≠ today low is real intraday.
  • Risk-per-trade is an editable field, not static text (owner § 10): per-conviction $ the user types; position recomputes. localStorage per ticket, like WS3’s “I took it.”
  • Earnings = hard amber card; Focus = footnote. No double-counting the screen gate as a ticket headline.

Cut from the prior mock: the “EOD” framing and its phantom second render state; the false “live 09:58” precision; any new backend column — atr_from_lod already ships from WS3 at 0.8/1.0, and earnings is re-derivable from the Earnings column already in picks.csv.
