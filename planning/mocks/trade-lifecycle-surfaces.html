Design intent

Actionable states, one glance

  • Severity stripe + pill carry state; numbers are secondary. The user decides in seconds pre-open of their workday.
  • Provisional banner is non-negotiable (ADR-011): a 9:45 number must never read as settled. Banner + timestamp + amber tint.
  • ATR-from-LoD renders only on actionable states (Triggered / Gapped-through) — it's an entry-quality gate, meaningless for Setting-up/Invalidated.
  • "I took it" on Triggered AND Gapped-through (owner 2026-08-07: gaps are takeable too, revisit later) — this is the WS3→WS5 handoff (creates a position, see WS5 mock).
  • Failed-breakout and No-quote are v1 states beyond the original four (owner-requested edge coverage): a tagged-then-failed setup ≠ still-setting-up, and a missing quote must never look like a vanished setup.
  • Further edge states noted for later: earnings-gapped-overnight (tag via the guardrail), and whipsaw (trigger + stop both hit same session).
  • Sort order = actionability: Triggered → Gapped → Failed → Setting-up → Invalidated → No-quote.
Future extension (owner 2026-08-07): a pre-close ~15:30 ET sibling of this surface — which of today's setups are confirming into the close so you can enter near the close, not wait a day. Pre-close collect trigger already exists (15:50); under ADR-011 Option C it's just another session value. Tracked as WS3b.

Design intent

The ticket answers "is this a good trade right now"

  • Stop menu is a segmented control, live-recomputing R, %-risk, and share count on selection — the ticket's one interaction.
  • No profit target anywhere, stated explicitly so the absence reads as a choice, not an omission (owner's ruleset).
  • Focus score demoted to a footnote — roadmap's "watchlist gate, not ticket headline" rule made visible.
  • Earnings guardrail is a hard amber card, not a chip — it should interrupt.
  • Risk-per-trade is a free input on the ticket (owner 2026-08-07): the user types their $ risk for this trade and shares recompute. Not a global constant — per-ticket, per-conviction. Add to WS4 scope; no config-table constant needed.
Resolved: risk-per-trade = free input on the ticket (not a fixed constant or % of account).

Design intent

State the engine holds so the user doesn't have to

  • Profit floor and active stop shown as two separate rows — the ADR-012 invariant made legible. Floor = the guarantee (monotonic, "never red again"); active stop = the working order (trails, may widen 20MA→50MA). The "widened" pill explains why the stop can sit on a lower basis without alarm.
  • Trim ledger is visible history ("7 ATR ✓ · 8 ATR ✓"), so an idempotent no-trim day is self-explanatory.
  • Caution state gets its own card treatment — the stateful two-close rule is the ruleset's subtlest part; the UI must show the counter, not just the outcome.
  • Exit awaits confirmed fill (owner 2026-08-07, confirmed): stop-hit puts the position in a closing state showing the modeled price as expected; the user confirms the actual fill (or "still holding" = discretionary override). Symmetric with entry — required for an honest R-multiple record.
  • Aggregate-exposure footer surfaces the roadmap's parked "crowding" idea as information only — total $ exposure, same-group clustering, and total open risk (heat = Σ(entry − current_stop)×qty). Never framed as "diversify."
Resolved: exit awaits confirmed fill (new closing state). Design-doc §4 currently auto-closes at the modeled price — needs updating to match; tracked on #264.
