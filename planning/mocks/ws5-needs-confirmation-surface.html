Why this shape

The surface is the same Closing-state cards from the existing WS5 mock — just hoisted to the top and grouped instead of sitting inline in date order. Nothing new to render; a re-sort of what the position list already contains.

Space budget (the real constraint)
  • Zero items → zero pixels. The strip is conditional (WHERE state='closing' is empty → not rendered). It never taxes the common case.
  • Collapsed is the default when items exist: a single ~64px strip + a header badge count. It costs about the height of one caution line, not a full card per item.
  • Expanded is opt-in (tap to open) and is exactly the exit-signal cards you already designed — so the "full card each" cost is paid only when the user chose to act on them.
  • The app-icon / header badge is the real backstop: it survives a missed push and is visible before any scroll. PWA Badging API where supported; header count always.
Behavior
  • Push is the nudge; this is the source of truth. If the one exit push is missed (iOS not installed-to-home, DND, offline), the item still surfaces here the next time the app opens — which a close-watching swing trader does daily.
  • Confirm fill → enter actual price → Closed (writes exit_price, confirmation_status='confirmed'). Still holding → back to Managing.
  • Auto-confirm countdown (review #5) lives right on the card so the "modeled, unconfirmed" fallback is never a surprise — the user sees the clock and can pre-empt it.
  • Order = urgency, oldest-signalled first (closest to auto-confirming), so the item about to be decided for you sits on top.
