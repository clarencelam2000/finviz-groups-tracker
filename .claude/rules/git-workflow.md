# Git Workflow Rules

## Session-start checklist

Run these before doing anything else:

```bash
git fetch origin
git log --oneline origin/claude/elegant-babbage-hlxnfy -5   # see if Actions pushed data overnight
git status                                                    # confirm clean working tree
```

Then check your branch position:
```bash
git log --oneline HEAD ^origin/claude/elegant-babbage-hlxnfy    # commits you have that default doesn't
git log --oneline origin/claude/elegant-babbage-hlxnfy ^HEAD    # commits default has that you don't
```

- If the second command shows commits → rebase before making any changes: `git rebase origin/claude/elegant-babbage-hlxnfy`
- If the first command is empty → your branch has nothing new; no PR needed, just work from here

## Branch lifecycle

- **New work**: always branch from `origin/claude/elegant-babbage-hlxnfy`, never from a stale local ref
- **Keep branches short**: land them before starting the next session — parallel branches doing the same work is the failure mode to avoid
- **After merge**: delete the source branch (GitHub UI if the git proxy returns 403 for `git push --delete`)
- **Identical to default**: if `git rev-parse HEAD` == `git rev-parse origin/claude/elegant-babbage-hlxnfy`, you're already landed; skip creating a PR

## Commit conventions

- GitHub Actions data commits: `data: snapshot YYYY-MM-DD` (auto-generated by workflow — do not manually replicate this format)
- Claude Code commits: conventional prefix + imperative mood
  - `feat:` new functionality
  - `fix:` bug corrections
  - `docs:` documentation only
  - `chore:` housekeeping (gitignore, deps, session notes)

## Detecting the parallel-branch problem

Before creating a new branch, verify the default branch doesn't already contain your intended changes:

```bash
git fetch origin
git diff origin/claude/elegant-babbage-hlxnfy -- scripts/   # check if scripts already match
```

If the diff is empty, the work is already landed. Orient from the current state rather than re-doing it.
